# 알림 (앱 안 알림 + 이메일) 설계

작성 2026-10-03. 크리에이터와 브랜드가 승인·반려·입금·정산·지급 같은 상태 변화를 직접 들어와 확인해야 하는 문제를 푼다. 운영자 알림은 지금처럼 Slack을 쓴다.

## 1. 결정 (2026-10-03)

- 경로: 앱 안 알림 + 이메일. 이메일은 Resend로 보내고, 키(`RESEND_API_KEY`)와 보내는 주소(`EMAIL_FROM`)가 있을 때만 보낸다.
- 다음 작업 순서: 알림 → 예산 증액 → 계정 연결 → 매니지드.

## 2. 구조

- **생성은 DB 트리거가 한다.** 상태 변화는 운영자 화면, RPC, 예약 작업 등 여러 경로에서 일어나므로, 표의 상태가 바뀌는 순간 `notifications`에 한 줄을 넣는다.
- **알림은 종류(`kind`)와 값(`data`)만 저장한다.** 제목과 본문은 앱의 순수 함수 `renderNotification()`이 만든다. 화면과 이메일이 같은 문구를 쓰고, 문구를 고쳐도 마이그레이션이 필요 없다.
- **이메일은 예약 작업이 보낸다.** pg_cron이 5분마다 `/api/cron/notification-emails`를 부른다. 이 라우트는 `notification_email_queue()`로 보낼 알림과 받는 주소를 가져와 Resend로 보내고 결과를 기록한다. 하루 넘게 지난 알림은 보내지 않는다(키를 나중에 넣었을 때 쌓인 알림이 한꺼번에 가지 않게). 실패하면 세 번까지 다시 보낸다.
- **화면**: 브랜드·크리에이터 상단 바의 종 아이콘에 안 읽은 개수를 띄운다. 누르면 최근 20개가 열리고 모두 읽음으로 바뀐다. 알림을 누르면 관련 화면으로 간다.

## 3. 데이터

`notifications`
| 칸 | 내용 |
|---|---|
| `user_id` | 받는 사람 (profiles, 탈퇴 시 함께 삭제) |
| `kind` | 아래 표의 종류 |
| `data` | 문구에 들어갈 값(캠페인 제목, 금액, 사유 등) |
| `link` | 누르면 갈 앱 경로 |
| `dedupe_key` | 같은 알림을 합치는 열쇠(주간 정산: `settlement:<주>`, 첫 클립: `first_clip:<캠페인>`) |
| `email` | 이메일로도 보낼지 |
| `email_sent_at`, `email_attempts`, `email_error` | 발송 기록 |
| `read_at`, `created_at` | |

사용자는 자기 알림만 읽는다. 읽음 처리는 `mark_notifications_read()`로만 한다.

## 4. 알림 목록

| 받는 사람 | 종류 | 언제 | 이메일 |
|---|---|---|---|
| 크리에이터 | `application_approved` / `application_rejected` | 지원 상태가 바뀔 때 | O |
| 크리에이터 | `clip_approved` / `clip_rejected` | 클립 상태가 바뀔 때(캠페인 중단 반려 포함, 사유 표시) | O |
| 크리에이터 | `settlement_created` | 주간 정산 행이 생길 때. 같은 주는 한 알림으로 합치고 금액을 더한다 | O |
| 크리에이터 | `payout_paid` | 지급 완료 | O |
| 크리에이터 | `dispute_resolved` | 이의제기 처리 | O |
| 크리에이터 | `view_report_reviewed` | 조회수 신고 처리(반영/미반영) | O |
| 크리에이터 | `campaign_closed` | 지원이 승인된 캠페인이 종료될 때 | X |
| 브랜드 | `campaign_live` | 입금이 확인돼 공개될 때 | O |
| 브랜드 | `deposit_short` | 받은 금액이 기록됐는데 아직 모자랄 때 | O |
| 브랜드 | `first_clip_approved` | 캠페인의 첫 클립이 승인될 때(캠페인당 한 번) | O |
| 브랜드 | `campaign_exhausted` | 예산을 모두 써서 종료될 때(중단은 브랜드가 한 것이라 제외) | O |
| 브랜드 | `leftover_finalized` | 중단한 캠페인의 남은 금액이 잔액으로 확정될 때 | O |
| 브랜드 | `refund_paid` | 남은 금액 반환·초과 입금 반환을 보냈을 때 | O |

## 5. 확인 필요

- 개인정보 처리방침에 '서비스 알림 이메일 발송'을 명시할지 [확인 필요]. 거래·서비스 안내라 수신 동의 대상은 아닌 것으로 보지만, 처리 목적에 적혀 있는지 확인한다.
- Resend 도메인 인증(`clipers.site`의 DKIM·SPF 기록)과 키 등록은 회사가 한다. 2026-10-03 확인 시 기록이 없다.

## 6. 테스트

- `renderNotification()`: 종류마다 제목·본문·금액 표기, 알 수 없는 종류의 기본 문구.
- `buildNotificationEmail()`: 제목, 본문, 앱 링크.
- 트리거: 운영 DB에서 트랜잭션 안에서 상태를 바꿔 알림이 생기는지 확인하고 되돌린다.
