# 예산 증액 설계

작성 2026-10-03. 성과가 좋은 캠페인에 돈을 더 넣으려면 지금은 새 캠페인을 만들어야 한다. 진행 중이거나 예산을 모두 써서 끝난 캠페인에 예산을 더할 수 있게 한다.

## 1. 결정 (2026-10-03)

| 항목 | 결정 |
|---|---|
| 최소 증액 | 100,000원 (부가세 별도 서비스 대금) |
| 대상 | 진행 중인 캠페인, 예산을 모두 써서 종료된 캠페인. 증액이 확인되면 종료된 캠페인은 다시 진행 중이 된다. 브랜드가 중단한 캠페인은 증액할 수 없다 |
| 결제 | 캠페인 입금과 같다. 계좌이체 + 세금계산서, 잔액 사용 가능, 운영자가 입금을 확인하면 예산에 더한다. 부족은 대기, 초과는 반환 |
| 종료 기간 조회수 | 다시 열린 캠페인은 마지막 정산 이후 늘어난 조회수를 이어서 정산한다(종료 기간 포함) |

## 2. 데이터

새 표 `campaign_topups`
| 칸 | 내용 |
|---|---|
| `campaign_id`, `brand_id` | |
| `amount` | 늘릴 서비스 대금(100,000원 이상) |
| `credit_applied` | 그중 잔액으로 낸 금액 |
| `received_amount` | 통장에서 확인한 누적 금액(부가세 포함) |
| `status` | `pending`(입금 알림) → `confirmed` |
| `requested_at`, `confirmed_at`, `confirmed_by` | |

- 캠페인당 처리 중인 증액은 하나만 둔다.
- 잔액 장부와 반환 표에 `topup_id`를 더한다. 캠페인당 한 번만 허용하던 '잔액 사용'·'초과 입금 반환' 유일성은 처음 입금분(`topup_id`가 비어 있는 행)에만 적용하고, 증액분은 증액마다 하나씩 허용한다.

## 3. 흐름

1. 브랜드가 캠페인 상세의 '예산 늘리기'에서 금액과 잔액 사용 금액을 넣고 '입금했어요'를 누른다. `request_topup(campaign, amount, credit)`가 대상·최소 금액·잔액을 확인하고, 잔액 차감과 증액 행 생성을 한 번에 한다.
2. 운영자 입금 확인 화면의 '예산 증액' 목록에서 받은 금액을 기록한다. `record_topup(topup, amount)`는 캠페인 입금과 같은 규칙을 따른다.
   - 모자라면 대기하고 브랜드에게 알린다.
   - 맞거나 넘치면 `campaigns.total_budget`에 증액분을 더한다. 넘친 금액은 반환 목록에 올린다.
   - 예산 소진으로 종료된 캠페인이면 `status = 'live'`, `finalized_at = null`로 다시 연다.
3. 크리에이터 지급 한도, 크리에이터 1명당 상한(예산의 15%), 기대 조회수는 모두 `total_budget`에서 계산하므로 따로 바꿀 것이 없다.
4. 알림: 브랜드에게 `topup_confirmed`(늘어난 금액, 다시 열렸는지)와 `topup_short`(확인된 금액, 차액).
5. 세금계산서: 운영자가 증액 입금분(잔액 사용분 제외)만큼 발행한다.

## 4. 약관

- 제9조에 7항 추가: 광고주는 진행 중이거나 예산을 모두 써서 종료된 캠페인의 서비스 대금을 100,000원 단위 이상 늘릴 수 있다. 입금·잔액 사용·부족·초과는 제2항, 제5항, 제6항을 따르고, 회사가 입금을 확인하면 캠페인이 다시 진행된다.
- 제5장 정산 3항: "캠페인 지급 한도에 도달하면 캠페인이 종료되고, 그 뒤 늘어난 조회수는 정산되지 않습니다. 다만 광고주가 서비스 대금을 늘려 캠페인을 다시 열면, 마지막 정산 이후 늘어난 조회수부터 이어서 정산합니다." 🔸

## 5. 테스트

- `validateTopUp`: 최소 금액, 정수, 잔액 사용 한도.
- `canTopUp(status, stoppedAt)`: 진행 중 가능, 예산 소진 종료 가능, 중단 불가, 초안·입금 대기 불가.
- DB: 운영 DB에서 트랜잭션 안에서 증액 요청 → 부족 → 확인(다시 열림) → 초과 반환 → 잔액 사용 유일성을 확인하고 되돌린다.
