# Clipers — UI/UX 리디자인 설계 (Whop Content Rewards 벤치마크)

> 근거 자료: 사용자 제공 Whop Content Rewards 스크린샷 18장(크리에이터 온보딩·홈·분석·제출·수익, 브랜드 홈·캠페인 생성 모달·캠페인 생성 폼, 디스커버·캠페인 상세), Whop 공식 디자인 시스템 `whopio/frosted-ui`(MIT) 토큰 소스, 공식 Clipers 로고(`packages/ui/brand/`).
> 추가 근거(2026-10-01): Content Rewards 공식 사이트(https://contentrewards.com/) 스크린샷과 배포 CSS — 제목 Suisse Int'l Medium(500), 본문 Inter, 자간 전 크기 -0.02em·제목 -0.03em, 제목 행간 0.85~1, 주 CTA는 pill + 촉감형 표면(라디얼 하이라이트 + 하단 립), 마케팅 페이지는 따뜻한 라이트 톤(#fffdfb 배경, #2d2518 텍스트). **이 사이트는 사용자가 지정한 메인 페이지(플랫폼 첫 진입 화면, `apps/site` `/`) 레퍼런스다** — 메인 페이지는 이 사이트의 구성(히어로 대형 타이포·CTA 2개·브랜드 월·기능 소개·FAQ·하단 CTA)과 따뜻한 라이트 톤을 기준으로 설계한다.
> 방향 결정(2026-10-01): `frosted-ui` 패키지를 직접 설치하지 않고 **토큰·컴포넌트 구조를 `packages/ui`로 이식**한다. 이유: 해당 패키지는 정식 릴리스 없이 카나리(`0.0.1-canary.161`)로만 배포되고 Tailwind v4를 요구한다.

## 1. 목표와 범위

**목표**: 기능 검증용 수준(인라인 스타일, 테이블 나열)인 현재 화면을 Whop Content Rewards 수준의 제품 UI로 끌어올리고, 코드 감사에서 확인된 구조 문제를 함께 해소한다.

**함께 해소하는 구조 문제**
- 두 앱의 `globals.css`에 같은 컴포넌트 CSS가 중복 → `packages/ui` 단일 소스
- 인라인 `style={{}}` 남발 → 컴포넌트/클래스로 대체
- `admin-workspace.tsx`(560줄)·`creator-workspace.tsx`(567줄)가 모든 섹션을 한 파일에서 처리 → 섹션별 라우트로 분리
- Tailwind v3가 설치돼 있으나 유틸리티 클래스 사용 0건 → 제거(패키지, 설정, 프리셋)
- 로그아웃 기능 부재 → 사용자 메뉴에 추가

**하지 않는 것 (빈 껍데기 방지)**: 전역 검색·AI·채팅·알림 아이콘, Whop의 멀티앱 좌측 레일, Discord 연동 카드, "60초 투어"·"런칭 콜 예약" — 모두 뒷받침할 기능이 없다. 결제 모델 선택(Retainer/Per post)도 저희는 CPM만 지원하므로 모델 선택 단계를 두지 않고, 요약 패널에 "모델: CPM"으로만 표시한다.

## 2. 디자인 시스템 (`packages/ui`)

**토큰** — Frosted UI에서 확인한 실제 값을 그대로 사용:
- 간격 `--space-1..9` = 4, 8, 12, 16, 24, 32, 40, 48, 64px
- 라운드 `--radius-1..6` = 3, 4, 6, 8, 12, 16px, `--radius-full` = 9999px
- 타이포 `--font-size-0..9` = 10~40px. 폰트는 Pretendard Variable(Inter 기반 라틴 + 본고딕 기반 한글, Apple SD 산돌고딕 Neo 대체용으로 설계) — 한국어 서비스에서 macOS 시스템 폰트와 가장 가까운 인상
- 그레이(다크) `--gray-1..12` = `#111111` … `#eeeeee` (Frosted dark gray 스케일 그대로)
- 브랜드 그린 스케일: 공식 로고 `#58B982`를 9단계로 두고 파생(solid/hover/text/alpha). 주 CTA는 촉감형 표면(상단 라디얼 하이라이트 + 하단 립), 장식용 선형 그라디언트는 쓰지 않는다
- 시맨틱: 성공=브랜드 그린, 경고/대기=Frosted amber, 위험=Frosted tomato, 정보=Frosted sky. 스탯 아이콘 틴트(그린/스카이/바이올렛/앰버)는 Whop 수익 화면 배색을 따름

**컴포넌트** (`packages/ui/src/components`, 스타일은 `cl-` 접두 클래스로 `packages/ui/src/styles/*.css`에 둔다)
- 기본: `Button`(모서리가 둥근 네모 — sm 6px / md 8px / lg 12px, 알약형은 `pill` 옵션으로 상단바·마케팅 헤더 CTA에만. primary는 Content Rewards식 촉감형: 상단 라디얼 하이라이트 + 하단 어두운 립 / secondary 회색 + 1px 베젤 / ghost, 비활성 상태), `IconButton`, `Badge`, `Avatar`, `Card`, `ProgressBar`
- 입력: `Field`(라벨 + 글자수 카운터 + 오류), `Input`, `Textarea`, `Select`, `Switch`, `Chip`(멀티선택), `OptionCard`(아이콘 원 + 우상단 라디오, 선택 시 브랜드색), `Dropzone`
- 데이터: `StatCard`(컬러 원형 아이콘 + 큰 숫자 + 라벨, 강조형은 그라디언트 틴트), `Tabs`(카운트 붙은 pill 세그먼트), `DataTable`, `EmptyState`(컬러 원 아이콘 + 제목 + 설명), `Timeline`(세로선 + 점 + 우측 합계), `Checklist`(완료 원 아이콘, `n of m` 카운터 + 진행바, 현재 단계 강조), `SummaryList`(키-값 행), `LineChart`(SVG, 격자선·축 라벨·마지막 날짜 강조)
- 오버레이: `Dialog`(네이티브 `<dialog>` 기반)
- 레이아웃: `AppShell`(상단바 + 사이드바 + 콘텐츠), `Sidebar`(섹션 그룹·활성 항목·배지), `PageHeader`(제목 + 우측 사용자 pill), `UserMenu`(로그아웃 포함), `StickyFooter`(검증 메시지 + 액션)

아이콘은 `lucide-react`(MIT)를 사용한다. 파일 출처 표기: 이식한 토큰 파일 상단에 Frosted UI MIT 저작권 고지를 남긴다.

**타이포·카피 규칙 (Whop 기준, 위반 금지)**
- 대문자 전용 라벨(`text-transform: uppercase`), 넓은 자간, 굵은 브랜드색 "아이브로(eyebrow)" 라벨을 쓰지 않는다. AI 템플릿처럼 보이는 가장 흔한 패턴이다.
- 섹션·사이드바 라벨은 문장형 대소문자, 중간 굵기(500~600), 중립 회색(`--gray-11`)으로 쓴다.
- 브랜드색은 CTA·활성 상태·진행도에만 쓰고, 장식용 텍스트에는 쓰지 않는다.
- UI 카피는 한국어로 쓴다. 영문 슬로건성 라벨("WORKSPACE", "Featured" 등)을 붙이지 않는다. 고유명사(Clipers, YouTube 등)만 영문을 유지한다.
- 제목 위에 위치를 알려 주는 보조 라벨을 두지 않는다. 위치는 사이드바 활성 항목과 제목이 알려 준다.

**질감 규칙 (Apple·Notion·Slack식 절제)**
- 굵기는 400/500/600만 쓴다(버튼 550). 700 이상 금지.
- 자간은 Content Rewards 기준으로 모든 크기 -0.02em, 제목 -0.03em, `word-break: keep-all`. 숫자(금액·조회수·표)는 `tabular-nums`.
- **테두리 선을 쓰지 않는다.** 면은 배경 톤으로 구분한다(페이지 gray-1 → 패널 gray-2 → 컨트롤 gray-3, 호버는 한 단계 밝게). 선택 상태만 브랜드 링, 표·리스트 내부엔 아주 옅은 구분선만 허용.
- 장식용 그라디언트·글로우·네온·큰 그림자 금지. 그림자는 팝오버와 주 CTA의 하단 립에만.
- 상단바·팝오버는 반투명 + 배경 블러(macOS vibrancy). 포커스는 3px 브랜드 알파 링.
- 탭은 세그먼트 컨트롤, 설정·동의 항목은 그룹 리스트(`List`/`ListRow`), 태그성 선택만 pill(`Chip`).

## 3. 앱 셸과 인증

- **상단바**: 좌측 로고(`clipers-wordmark.svg`), 우측 — 크리에이터는 잔액 pill(정산대기+지급요청 합계), 공통으로 사용자 아바타 메뉴(역할 표시, 로그아웃)
- **사이드바**: 역할별 섹션 그룹(아래 4~6절). 모바일(≤768px)에서는 햄버거로 여닫는 드로어
- **로그인/가입**: 새 컴포넌트로 재작성. 가입 직후 온보딩으로 이동

## 4. 온보딩

- **역할 선택**("무엇을 하고 싶으세요?"): "수익 창출 시작하기"(추천 배지, 크리에이터) / "캠페인 개설하기"(브랜드). 기존 가입 시 역할 라디오를 대체한다 — 역할은 여기서 확정되므로 `handle_new_user`는 기본 `creator`로 생성하고, 브랜드 선택 시 역할을 바꿔야 한다. `prevent_profile_role_escalation` 트리거가 본인 역할 변경을 막으므로, **온보딩 완료 전 1회에 한해 creator↔brand 선택을 허용**하는 SECURITY DEFINER 함수 `complete_onboarding()`을 둔다(admin으로의 전환은 불가). 역할 가드 트리거는 `onboarding_completed_at`·`terms_agreed_at` 직접 수정도 막는다. 기존 계정은 온보딩 완료로 백필(약관 동의일은 비움).
- **크리에이터 단계**: 수익 방식 안내(클리핑 / UGC / 검수와 정산 — `campaign_content_type` 기준) → 관심 분야 칩(최대 3개) → 카메라 노출 여부(2×2 카드) → 활동 단계(2×2 카드) → 약관·개인정보 동의(링크 카드 + 토글) → 크리에이터 홈. 상단 진행바 + 뒤로가기.
- **브랜드**: 약관 동의 → 브랜드 홈(체크리스트)
- **데이터**: `profiles`에 `onboarding_completed_at`, `interests text[]`, `on_camera text`, `experience_level text`, `terms_agreed_at` 추가. 온보딩 미완료 사용자가 워크스페이스에 접근하면 미들웨어가 `/onboarding`으로 보낸다.
- **약관/개인정보 페이지**: 문구가 아직 없으므로 `/terms`, `/privacy`를 "준비 중" 안내 페이지로 둔다(법률 검토 후 교체 — 명시적 미완 항목).

## 5. 크리에이터 워크스페이스 (`/creator/*`)

사이드바: **탐색**(홈, 캠페인, 디스커버↗) / **내 활동**(분석, 제출 현황, 수익) / **계정**(설정)

- **홈**: "좋은 저녁이에요, {이름}" + "셋업 마무리" 체크리스트(계정 생성 ✓ / 첫 캠페인 지원 / 첫 클립 제출 / 첫 정산 — 실제 데이터로 완료 판정) + 잔액 카드(획득·조회수·참여 캠페인·제출 수)
- **캠페인**: 내가 지원한 캠페인(상태 배지) + 지원 가능한 캠페인 카드. 승인된 캠페인에서 "클립 제출" 다이얼로그
- **제출 현황**: 탭 `승인 n / 대기 n / 반려 n`. 반려 클립에 이의제기, 자동수집 불가 플랫폼 클립에 조회수 신고 — 기존 기능을 다이얼로그로 이전. 빈 상태 컴포넌트
- **수익**: 잔액 카드(받을 금액/지난주/이번 달/누적 — 정산이 주 단위(`period` = KST 월요일)라 '오늘' 금액은 근거 데이터가 없어 제외, 금액은 원천징수 전 기준이고 표에 실지급액 표시) + 타임라인 `정산 대기(pending) → 지급 요청(requested) → 지급 완료(paid)`, 각 단계 합계. 정산대기 건에 "지급 요청"
- **설정**: 이름·관심 분야·얼굴 노출·숏폼 경험 수정(온보딩과 같은 컴포넌트 재사용)
- **구조**: 페이지는 서버 컴포넌트에서 데이터를 읽고, 지원·제출·이의제기·조회수 신고·지급 요청만 클라이언트 컴포넌트로 둔다. 워크스페이스 셸은 역할별 `layout.tsx`가 렌더링
- **분석**: 스탯 카드(조회수·획득·제출·승인) + 누적/일별 조회수 라인차트 + 플랫폼 필터 + 기간 선택(7/30/90일)

## 6. 브랜드 워크스페이스 (`/brand/*`)

**가격 정책 (2026-10-01 결정)**: 브랜드는 검증 조회수 1천 회당 3,000원(`brand_cpm`), 크리에이터는 1천 회당 800원(`creator_cpm`)을 받고 차액이 플랫폼 수익. 둘 다 캠페인별 기본값이며 운영자만 조정(DB 트리거가 강제). 최소 예산 1,000,000원. 브랜드는 단가를 입력하지 않고 예산만 정하며, **브랜드 화면에는 크리에이터 단가·지급액을 노출하지 않는다**(예산 사용액은 크리에이터 지급액 × 브랜드/크리에이터 단가로 환산). 클립당 최대 예산은 브랜드 지출 기준으로 입력받아 크리에이터 지급 상한으로 환산해 저장. 정산의 캠페인 상한은 총예산 × 크리에이터/브랜드 단가.

사이드바: **개요**(홈, 캠페인) / **관리**(분석, 예산 사용 내역) / **브랜드**(설정). 상단바에 '캠페인 만들기'(pill CTA)

- **홈**: 히어로("첫 캠페인을 라이브로 만들어 보세요") + "시작하기" 체크리스트 `n of 4`: 캠페인 만들기 → 예산 입금(입금 완료 표시) → 운영팀 확인 대기 → 라이브. 실제 캠페인 상태로 판정. 캠페인이 하나라도 라이브면 대시보드(스탯 카드 + 캠페인 목록)로 전환
- **캠페인 생성** (`/brand/campaigns/new`, 전체 화면): 상단 "← 캠페인 목록" + 진행률, 좌측 섹션 — 이름·설명(글자수 카운터) / 콘텐츠 유형·카테고리 / 썸네일(16:9 드롭존) / 플랫폼별 요율 / 예산·검수 SLA / 참고 자료(링크 여러 개) / 콘텐츠 요구사항, **우측 고정 요약 패널**(과금 방식 '조회수 1천 회당 3,000원', 공개 범위·지원서 심사, 이름, 유형, 카테고리, 플랫폼, 예산, 예상 조회수), **하단 고정 푸터**(첫 번째 검증 오류 메시지 + "임시저장" + "다음"). "다음" → 캠페인 상세의 입금 안내. 임시저장 = `draft`로 저장 후 목록으로(스키마 필수값 때문에 검증 통과 후 저장). 초안 수정은 같은 화면(`?draft=id`)
- **캠페인 상세** (`/brand/campaigns/[id]`): 상태 배지, 입금 안내(초안일 때), 스탯 카드, 제출 클립 목록(읽기 전용), 정산 합계
- **분석**: 소유 캠페인 전체의 조회수 차트·지출·제출 수
- **예산 사용 내역**: 캠페인별 입금 예산·사용·잔액·검증 조회수(브랜드 단가 기준, 읽기 전용)
- **데이터**: `campaigns.description text` 추가, `reference_url`을 `reference_links text[]`로 전환(기존 값 이관). 이 단계에서 `apps/site` 캠페인 상세의 참고자료 표시도 새 컬럼으로 함께 바꾼다(컬럼 제거로 상세 페이지가 깨지지 않도록). 영상·이미지·브랜드 에셋 업로드(Whop의 참고자료 업로드)는 이번 범위 밖

## 7. 운영자 워크스페이스 (`/admin/*`)

- 현재 한 파일의 섹션을 라우트별 페이지로 분리하고 각 목록을 `DataTable` + 행 액션으로 재구성. 사이드바 항목에 대기 건수 배지
- **현황**: SLA 초과·이상 트래픽 경고 배너 + 대기 건수 + 캠페인 현황 테이블(브랜드 사용액 진행바, 크리에이터 지급액, 플랫폼 수익 = 사용액 − 지급액). 이상 트래픽 목록도 이 화면에
- **캠페인(운영자)** `/admin/campaigns/[id]`: 예산·수익 요약, 브랜드/크리에이터 단가 조정(크리에이터 단가 ≤ 브랜드 단가, 다음 정산부터 적용), 입금 확인
- **사이드바**: 개요(현황) / 검수(지원서, 클립, 조회수 신고, 이의제기) / 정산(입금 확인, 주간 정산), 각 대기열 건수 배지

## 8. 마켓플레이스 (`apps/site`)

- **디스커버**: 좌측 사이드바는 **분야 필터**(모든 캠페인 + 관심 분야 5개 그룹 — 안내 페이지는 메인 페이지 단계 전까지 빈 껍데기라 링크하지 않음) + 그린·라임 배경 광원 히어로 + 서버 검색(`?q=`, JS 없이 동작) + 추천 캠페인 레일(남은 예산 순) + 캠페인 카드(썸네일, 브랜드, 플랫폼, '1천 회당 800원' 배지, 남은 예산·진행바) + 인기 클립
- **공개 단가**: 크리에이터 단가만 노출(Whop 방식). 브랜드 단가·브랜드 사용 단가는 공개 페이지·llms.txt·구조화 데이터 어디에도 노출하지 않음
- **캠페인 상세**: 그리드 위 **모달**(인터셉팅 라우트 `@modal/(.)campaigns/[id]`) — 뒤로·전체화면·링크복사 버튼, 배너, "모집 중" 배지 + 플랫폼 아이콘 + 참여자 수 + "지원하기", 플랫폼별 요율 카드 그리드, 예산 카드("₩n 남음" + 진행바), 요구사항·참고자료, 리더보드(1~3위), 누적 조회수 차트. 직접 URL 접근 시에는 같은 내용을 전체 페이지로 렌더링

## 8-1. 검색·AI 노출 (SEO / GEO / AEO)

- 공개 사이트만 색인: `apps/site` robots 허용 + `sitemap.xml`(진행 중 캠페인 자동 포함), `apps/app`은 robots 차단 + `noindex`
- 페이지별 메타데이터: 고유 title·description·canonical·OG(캠페인 썸네일)
- 구조화 데이터(JSON-LD): 사이트 전역 Organization + WebSite(SearchAction), 디스커버 CollectionPage + ItemList, 캠페인 WebPage + Offer(크리에이터 단가, 1천 검증 조회수 단위) + BreadcrumbList
- `llms.txt`: 서비스 요약, 크리에이터·브랜드 이용 방식, 진행 중 캠페인 목록 — AI 답변 엔진용
- 남은 항목(메인 페이지 단계): 서비스 소개 본문과 FAQ(+ FAQPage 구조화 데이터) — 답변 엔진이 인용하는 핵심 콘텐츠

## 9. 테스트와 검증

- 새 순수 로직은 `packages/db`에 TDD: 체크리스트 단계 판정(크리에이터·브랜드), 수익 기간별 집계(오늘/주/월/누적 — 한국 시간 기준), 캠페인 생성 폼 검증, 온보딩 입력 검증
- 컴포넌트는 빌드/타입체크로 확인(브라우저 자동화 도구 없음 — 시각 확인은 사용자가 로컬에서 수행)
- 데이터 흐름이 바뀌는 단계(온보딩 역할 전환 함수, 스키마 변경)는 이전과 같이 실데이터 e2e 스크립트로 검증
- 마이그레이션은 MCP로 적용 후 버전에 맞춰 로컬 파일명 정리(기존 절차)

## 10. 진행 순서 (단계별 별도 구현 계획)

1. 디자인 시스템 + Tailwind 제거 + 앱 셸(상단바·사이드바·사용자 메뉴·로그아웃)
2. 인증·온보딩(스키마 변경 포함)
3. 크리에이터 워크스페이스
4. 브랜드 워크스페이스(스키마 변경 포함)
5. 운영자 워크스페이스
6. 마켓플레이스(디스커버 + 상세 모달)
7. 메인 페이지(`apps/site` `/`, contentrewards.com 레퍼런스) — 기획·카피는 사용자와 함께 확정

각 단계는 끝날 때마다 빌드·테스트가 통과하는 동작 가능한 상태로 커밋한다.
