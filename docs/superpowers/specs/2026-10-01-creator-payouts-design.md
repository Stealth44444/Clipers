# 크리에이터 지급 정보 · 3.3% 원천징수 설계

작성 2026-10-01. 파일럿에서 크리에이터에게 실제로 돈을 보내기 위해 필요한 계좌·실명·주민등록번호 수집, 사업소득 원천징수, 신고 자료를 정한다. 세법·개인정보 내용은 조사 결과이며, 운영 전에 세무사와 변호사 확인을 받는다.

## 1. 조사 결과 요약

| 주제 | 내용 | 설계에 반영 |
|---|---|---|
| 소득 구분 | 캠페인 참여는 계속·반복적이므로 사업소득으로 본다. 1인 미디어 창작자(인적·물적 시설 없음) 업종코드는 **940306**(면세 인적용역). | 사업소득 3.3%, 신고 자료 업종코드 940306 |
| 세율 | 소득세 3% + 지방소득세(소득세의 10%) = 3.3%. 10원 미만 절사. | `payoutTax()` |

| 간이지급명세서 | 사업소득은 **매월** 제출, 지급일이 속한 달의 다음 달 말일까지. 성명·주민등록번호·지급액·세액·업종코드. | 운영자 화면에서 월별 CSV |

| 보관 기간 | 세무 장부·증빙 5년(국세기본법 제85조의3). | 마지막 지급 후 5년 보관(파기 절차는 약관·처리방침에 명시, 자동 파기는 후속 작업) |

## 2. 데이터

- `payout_accounts` (크리에이터당 1행): 실명, 은행 코드, 계좌번호, 생년월일, 주민등록번호 암호문(`rrn_ciphertext`), 갱신 시각. 암호문 칸은 API로 읽을 수 없다(칼럼 권한). 쓰기는 앱 서버(서비스 키)만.
- `payouts` (지급 요청 1건 = 1행): 정산액 합계(원 단위 버림), 소득세, 지방소득세, 이체할 금액, 요청 당시 실명·은행·계좌 사본, 상태(`requested` → `paid`), 요청·지급 시각.
- `settlements.payout_id`: 어느 지급에 묶였는지.
- `pii_access_logs`: 주민등록번호 원문을 꺼낸 기록(누가, 언제, 무엇을, 몇 명).

## 3. 흐름

1. 크리에이터가 설정의 '지급 정보'에서 실명·은행·계좌·주민등록번호를 입력한다. 서버가 형식(주민등록번호 검증, 만 19세 이상)을 확인하고 암호화해 저장한다.
2. '지급 요청'을 누르면 `request_payout()`이 대기 중인 정산을 모두 묶어 `payouts` 1행을 만들고 세금을 계산한다. 지급 정보가 없으면 거절한다. 최소 요청액 3,000원(정산액 기준)은 그대로.
3. 운영자는 '지급 요청' 목록에서 이체할 금액·실명·계좌를 보고 이체한 뒤 '지급 완료'를 누른다(`mark_payout_paid()`, 정산 행도 함께 지급 완료).
4. 매월 초 운영자가 지난달 지급분 CSV(간이지급명세서·원천세 신고용)를 내려받는다. 주민등록번호 원문이 들어가므로 접근 기록을 남긴다.

## 4. 결정 대기(코드 밖)

- 전자금융거래법상 지급 구조(위 표 마지막 행) — 변호사.
- 세율·소액부징수·업종코드·신고 주기 — 세무사.
- 미성년자 참여 정책(법정대리인 동의 절차를 만들지) — 대표.
- 계좌 실명 확인 API 도입 시점.
