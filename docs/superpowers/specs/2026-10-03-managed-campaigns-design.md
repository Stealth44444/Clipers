# 매니지드 캠페인 설계

작성 2026-10-03. 영업·상담으로 조건을 정한 캠페인을 운영자가 브랜드 대신 만든다.

## 1. 결정 (2026-10-03)

| 항목 | 결정 |
|---|---|
| 개설 | 운영자가 브랜드 계정을 골라 대신 만든다. 단가(브랜드·크리에이터)와 예산을 계약대로 정한다 |
| 공개·지원 | 셀프서브와 똑같다. 마켓에 공개되고 누구나 지원하며, 승인·검수·정산·지급도 같다 |
| 소스 유출 방지 | 이번 범위에서 뺀다(워터마크 등은 나중에 따로) |

## 2. 구조

- 공개·지원·검수·정산 경로(DB 함수 4개, 정책 7개, 앱 쿼리 3곳)는 `track = 'self_serve'`를 기준으로 열려 있다. 매니지드도 같은 경로를 써야 하므로 `track`은 `self_serve` 그대로 두고, **`campaigns.managed_by`(만든 운영자)**로 매니지드를 표시한다. 기존 `track = 'managed'` 값은 쓰지 않는다.
- 운영자 화면 `/admin/campaigns/new`: 브랜드 계정, 캠페인 정보(브랜드 작성 화면과 같은 검사), 브랜드 단가·크리에이터 단가(기본 3,000원·800원, 브랜드 단가 ≥ 크리에이터 단가)를 넣으면 서버(서비스 키)가 캠페인을 **입금 확인 대기(`pending_escrow`)**로 만들고 플랫폼별 단가 행을 넣는다. 입금은 계약대로 받고 기존 '입금 확인' 화면에서 처리하면 공개된다.
- 브랜드 화면: 캠페인 상세에 "Clipers 운영팀이 관리하는 캠페인이에요"를 보여 준다. 증액·중단·결과 보기는 셀프서브와 같다.
- 운영자 캠페인 상세에 '매니지드' 표시.

## 3. 데이터

- `campaigns.managed_by uuid references profiles(id)` — 비어 있으면 셀프서브. 로그인 사용자에게 조회 권한(익명 제외).

## 4. 테스트

- `validateManagedPricing`: 정수, 크리에이터 단가 > 0, 브랜드 단가 ≥ 크리에이터 단가.
- 운영 DB: 운영자가 만든 캠페인이 입금 확인 뒤 공개되고 크리에이터가 지원할 수 있는지(트랜잭션 안에서 확인 후 되돌림).
